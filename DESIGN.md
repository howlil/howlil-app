# Portfolio Design Contract

## Purpose

The portfolio should feel authored by an engineer, not assembled from a portfolio template or generated from a checklist. The visual identity is **industrial technical editorial**: direct, asymmetric, restrained, and content-led.

## Hierarchy

1. Engineering identity must be unmistakable above the fold.
2. One flagship project carries the strongest visual and narrative weight.
3. Supporting projects are intentionally lighter; do not repeat the flagship composition for every item.
4. Experience and writing are reference surfaces, not equal-weight homepage sections.
5. Prefer hierarchy through type scale, whitespace, alignment, offset, and density before borders or containers.
6. Repetition must have a functional reason. Repeating the same section header, three-column summary, card, or metadata treatment is considered template drift.

## Visual vocabulary

Use:
- warm neutral page and surface tokens;
- large, decisive sans-serif typography on identity and navigation surfaces;
- readable serif typography only where long-form reading benefits from it;
- deliberate asymmetry built on a stable grid;
- thin structural rules used selectively;
- near-zero shadow and restrained radius;
- monospace only for actual metadata such as indices, dates, or code;
- real product screenshots or media only when they add evidence;
- functional motion for navigation, focus, disclosure, and media inspection.

Avoid by default:
- architecture or workflow diagrams as portfolio decoration;
- decorative gradients or glow;
- glass cards and floating panels;
- decorative bento layouts;
- fake terminals or random code backgrounds;
- logo clouds and decorative metric widgets;
- excessive pills/chips;
- repeated Problem / Decision / Result grids across lists;
- large rounded cards without a structural reason;
- 3D/WebGL decoration;
- animation added only to make the portfolio feel dynamic;
- explanatory copy under every section heading.

## Composition rule

A page should establish clear pacing rather than repeating one component grammar from top to bottom.

For the homepage, preserve this order of emphasis:

1. identity statement;
2. one flagship engineering story;
3. compact supporting work;
4. concise professional history;
5. notes/writing index.

Do not make all five surfaces visually equivalent.

## Decision rule

Before adding a visual treatment, it must materially improve at least one of:

- information hierarchy;
- comprehension;
- navigation or interaction feedback;
- evidence quality;
- distinctive product identity.

If it does not, do not add it.

## Responsive rule

Mobile preserves the same hierarchy rather than creating a different product. Large identity type may scale down aggressively, but the flagship must remain dominant and supporting work must remain concise. No composition may create horizontal page overflow, and interactive targets remain touch-safe.
